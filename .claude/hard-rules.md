# Hard rules (always, no exceptions)

Each rule points to the decision that justifies it (`decisions.md`).

1. **Angular 14 only** (the repo's version): NgModules, constructor injection, RxJS 7.5, strict TypeScript 4.7. No signals, standalone components, `@if/@for` or later APIs.
2. **Do not touch** `src/main/**` (backend), `resources/*.json` (sample invoices) or `pom.xml`. If something is wrong there, only report it. (D9)
3. **Self-contained units** (D14, D11): `app/app/{styles,helpers,components,core,pages,features}`. `features/` is business only (today `invoices`) and never imports another feature's internals; `core/{i18n,theme,settings,menu}` is the app infrastructure that anyone may import; shared pieces are `components/`, `helpers/`, `styles/` and `core/`. A page only composes features, core and components (D74). Inside a feature: `components, services, store, types, helpers`. Where a helper, constant or base class lives is decided by who uses it (D70, D77): one unit → inside that unit (`helpers/`, `<unit>.defaults.ts`); several units → `helpers/` at the app root (functions, one file per context) or `core/` (infrastructure such as the `Store` base class and the generic CRUD service, store and mock in `core/crud` (D78) and file import in `core/import` (D79)). A unit with a few small helpers keeps them in one `<unit>.helpers.ts`; a `helpers/` folder only when it has sub-structure.
4. **Always typed** (D10): no `any`; no `typeof`/`if` chains to detect formats; each format = raw type + `detect` + `toDraft` + one registry line.
5. **UI kit** (D16, D40): components with `@Input` + stackable CSS classes namespaced by component; colors, typography (font sizes, weights, line heights), opacity (`--opacity-full`, `--opacity-disabled`, `--opacity-hidden` and the color tints), border radius, z-index layers, motion (durations, easing, scale), spacing, borders and sizes only through design variables (`var(--color-primary)`, `var(--font-size-sm)`, `var(--space-2)`, `var(--radius)`...; no hex or raw value outside `styles/_palette.scss`, `_tokens.scss` and `_breakpoints.scss`); element defaults (`h1`–`h6`, `p`, `small`, `strong`, `a`...) come from `styles/_base.scss` and the repeated looks are base classes (`.text-label`, `.empty-state`, `.section`); a component only overrides what is specific to it; NEVER hardcoded text in views or components (always the `t` pipe or the translate service, keys in ca and es; this includes the page title, `aria-label`s, placeholders, toasts and dialog messages).
6. **Errors and toasts** (D12, D15, D4): 5 s toast (info/success/warning/error). Blocking = malformed JSON, missing base, unknown format and (deliberately, D47) an empty number → not created. Everything else informative. A repeated invoice number updates the existing invoice (D52). Failed action → error toast always, unless the action sets `toasts: false` (the import does, its results are in the table: D80); success toast by default only for create/update/delete, and for reads only by prop.
7. **Tests** (D20, D58): Jasmine/Karma, deliberately small: the logic the exercise needs plus component tests only for the Button and the Drawer (samples); written with each story and green before every commit.
8. **Simplicity:** only what the README and the decisions ask for. No new dependency without deciding it first.
9. **Git** (D18, D23, D25, D26, D27): local identity `danimo17`; never the work email; never push to `main`; a single branch `feat/invoices-upload`; do not commit `src/main/resources/static`; no Claude attribution in commits or the PR.
10. **Update discipline** (D37): every new decision or rule, or change to a story, is written in the same step to **all** affected files (`decisions.md`, `hard-rules.md`, `stories.md`, `CLAUDE.md`, README). No stale file.
11. **Cards below the page header** (D28, D29, D31, D33, D45): the page title and its actions go OUTSIDE any Card, in a `page-header`; everything below it, and the content of Dialog/Drawer, goes in `Card`. Card header = actions that start something on that card; footer = actions that confirm or resolve. Outside the rule: page header, Toast and side menu. The header of a Dialog/Drawer is the Card header: an optional title plus actions, and header actions are icon-only (D53); both always have a close icon and take extra header actions (D54). Whatever a Dialog/Drawer shows is changed or reset only on `afterClosed`, never while it animates out (D81). **Never a Card inside a Card:** Dialog and Drawer are shells that render a single Card (Drawer: `square` + `fullHeight`).
12. **Environment:** `source ~/.nvm/nvm.sh && nvm use 18.17.0` before any `npm`/`ng`. Test builds with `--output-path` to a temporary directory. (`./mvnw spring-boot:run` uses its own Node 14 + npm 6, see rule 18.)
13. **Language** (D41): everything in English (code, identifiers, comments, file and folder names, tests, commits, PR, `.claude/`, i18n keys). Only exceptions: the ca/es values in `features/i18n/translations/*.json` and the justification section of the README (Catalan). Talk to the author in Catalan.
14. **No repeated code (DRY)** (D39): one behavior = one place. General component with boolean/content props instead of copies; helpers/services for cross-cutting actions (`ConfirmService`, `withToasts`, `NotificationService`); centralized defaults; severities in a single list. Before writing something a second time, turn it into a prop, helper or component.
15. **Naming** (D40): kebab-case in CSS/SCSS (classes, variables, files) and file names; Angular style guide in TypeScript (PascalCase classes, camelCase members, suffixes `.component/.service/.module/.pipe`, selectors prefixed `app-`); every component has its own `.html` and `.scss` (no inline template or styles) and its helpers in a `helpers/` folder next to it (D69). Simple but pleasant and uniform visuals; no time spent on a graphic identity.
16. **Typing and lint** (D42, D43): type everything — inputs, outputs, events, configs, parameters and return values; no `any`. `npm run lint`, `npm run format:check`, the tests and the build must pass for every story, before its commit.
17. **Lists of buttons/links** (D55): always through `app-button-list` (props `orientation`, `wrap`; configs or projected items), whose `btn-list` classes and `borderless` marker set the spacing; never hardcode the spacing between buttons or links in a component's own CSS.
18. **Running with Spring Boot** (D57, D59, D26): the app uses hash routes (`/#/invoices`) so reloading a page works behind Spring Boot; `@types/node` stays pinned (`~18.19`) because the Maven build runs Node 14 + npm 6 and ignores the lockfile; `./mvnw spring-boot:run` and `npm run build` rewrite `src/main/resources/static` — never commit it.
19. **No comments in the source files** (D66): not in TypeScript, templates or styles. Explanations, decisions and notes live in `.claude/` (`decisions.md` for the why, `hard-rules.md` for rules); the code explains itself through names and types.
20. **Types in their own files, grouped by unit** (D71): no `interface`/`type` declared in the same file as functions, classes or components; one `.types.ts` per component or business unit holding all its coherent types (`components/button/button.types.ts`, `features/invoices/types/invoices.types.ts`, `core/i18n/types/i18n.types.ts`, `helpers/*.types.ts`), never one file per type; split it only when the unit grows.
21. **Translations are nested JSON** (D72): add keys inside their group; a key is either a text or a group, never both. The dotted key is what code and templates use. Shared words and actions are reused, never copied per element (D76): `common.field.*`, `common.action.*` (with `{entity}` from `entity.*` through `entityParams`), `pages.*`.
22. **Nothing declared and not used** (D73): when a change makes a variable, import, parameter, constant, type, export, translation key or style obsolete, remove it in the same change. `noUnusedLocals`/`noUnusedParameters` and ESLint enforce part of it; the rest is reviewed.
23. **Modern JavaScript** (D75): ES2020 by default — `const` arrow functions for standalone helpers (implicit return for one-expression bodies), spread, destructuring, `?.`, `??`, `Array`/`Object` methods instead of manual loops and accumulators; no `var`, no `function` declarations outside classes.
