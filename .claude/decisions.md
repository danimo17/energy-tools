| D10 | Automatic format detection with an extensible registry: each format has `detect(json)` (checks its own keys, no `typeof` chains) + `toDraft(json)` to a common draft. | D12 | BLOCKING (not created): malformed JSON, missing or non-numeric taxable base, unrecognized format (the README's blocking cases) and, deliberately, an empty invoice number (D47). A repeated number is not a warning any more: it updates the existing invoice (D52) | "What the README says" plus one deliberate demo case; do not invent more blocking cases | S3, S9 |

A format only declares `detect` and `toDraft`; a new format with a rule of its own would add it to the list guarded by its own field. Replaces the per-format rule lists | Author's decision: never warn about a field that invoice type will never have, with the least structure | S3, justification |
